## Summary
This source captures the PowerShell documentation style rules for Markdown, syntax blocks, code samples, and cmdlet-reference formatting. It is the most procedural of the documentation sources and focuses on how PowerShell docs should be written, not just what they should cover.

## Key Claims
- PowerShell docs should use correct Pascal-cased command names, avoid aliases unless they are the point, and format syntax consistently
- Code samples should use fenced code blocks and avoid line-continuation backticks when possible
- Cmdlet reference pages follow PlatyPS schema rules, including strict section ordering and example formatting
